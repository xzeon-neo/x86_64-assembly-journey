
Execution flow — how the CPU moves through code

Think of your assembly code as a list of instructions, written one after another, like a to-do list:

instruction 1
instruction 2
instruction 3

By default, the CPU does them in order, top to bottom — finish instruction 1, go to instruction 2, then instruction 3, and so on. This "just go to the next line" behavior is called sequential execution. It's the default — unless something tells the CPU to do otherwise.

That "something" is JMP.

***MOV — copying values***

MOV copies a value from one place to another.

MOV destination, source


![new_MOV_JMP](../Attachments/new_MOV_JMP.png)

Simple as that — the name says "move" but really it's "copy." Nothing gets erased from the source.

JMP — breaking the normal order

Normally, code just runs top to bottom. JMP is how you break that — it tells the CPU "don't go to the next line, go somewhere else instead."

Why this matters

That's really it for today — two ideas:

Code normally runs top to bottom, one line after another.
JMP lets you break that order and send execution somewhere else entirely.
